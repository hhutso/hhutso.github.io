WaterOptix

Overview

Problem
During a drought, farmers must decide whether to fallow land or buy water, which crops to prioritize, and whether to trade, with little analytical support.
Who it affects
Farmers and water managers in the Rio Grande Basin (EBID and MRGCD irrigation districts).

Architecture

The decision flow

A farmer enters an irrigation district, an expected shortage level, water trading access and a crop portfolio. The tool returns ranked adaptation strategies by income preserved, crop-by-crop acreage adjustments, an income comparison across trading institutions, and a plain-English buy vs. fallow recommendation based on shadow prices.

Code layout

A React frontend (components, pages and services) talks to a FastAPI backend (data, models and services). I built the frontend.

Key decisions and why

The model comes from published research (Ward, 2025), which uses Positive Mathematical Programming to simulate water trading under drought using 2017 to 2021 data. The backend serves that paper's scenario tables, so the numbers trace back to a source. The buy vs. fallow advice is written in plain English so farmers do not need to read shadow prices.

Status

WaterOptix is a hackathon prototype built on scenario tables from one paper, covering the EBID and MRGCD districts only.

Tech stack

  • Frontend: React, Vite, Tailwind CSS, Recharts
  • Backend: Python 3.11, FastAPI
  • Data: Ward et al. 2025 scenario tables
