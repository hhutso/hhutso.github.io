Capstone Project / Fall 2026

StoryWeave

Overview

Problem
Young children need reading practice at the right level, but most stories are not matched to the phonics patterns a child has already mastered.
Who it affects
Children in grades 1 to 3, and the parents and caregivers who guide their practice.
My role
Fullstack developer, mainly the child and parent interfaces.

Architecture

The learning loop

A child reads a story aloud one line at a time. Azure Speech scores each word as mastered, shaky or missed, and the browser shows the result in color. Mastery is saved per phonics pattern. The difficulty engine then picks the patterns for the next story: ones the child has mastered plus two new ones. Claude writes the story from those patterns.

Code layout

The backend is split into routes (HTTP endpoints), services (scoring, difficulty and story generation) and models (13 database tables). The React frontend has separate child, parent and API modules. I worked mostly on the child and parent modules.

Key decisions and why

Stories are generated from an approved list of 316 words, so they stay readable at this level. If generation fails three times, the child gets a pre-written story instead of an error. Audio is processed per line and never stored, to limit what we keep about children.

Quality

Checks

The backend is tested with pytest and linted with ruff. Database changes go through Alembic migrations so everyone's schema stays in sync.

Team workflow

The team shares one hosted PostgreSQL database, so we check with each other before running scripts or migrations against it. Vocabulary and demo data are loaded by seed scripts, so a fresh setup can be rebuilt.

Status and next steps

StoryWeave works end to end, but it is not ready for real children's data. Login and PINs are placeholders, there is no consent flow or retention policy yet, and the parent dashboard uses placeholder data.

Known limitation

Claude often uses words outside the approved list, so most children currently get a pre-written story. Fixing this is the first task of the next sprint.

Next

Replace the placeholder login with real authentication, then connect the parent dashboard to real data.

Tech stack

  • Backend: Python 3.12, uvicorn, managed with uv
  • Frontend: React, Node.js 22
  • Database: PostgreSQL (Docker locally, Neon shared), Alembic migrations
  • Services: Claude Haiku 4.5 for stories, Azure Speech for scoring, FFmpeg for audio
