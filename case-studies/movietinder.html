Architecture

The swipe loop

The user drags a movie card right to like it or left to skip it. The buttons do the same. Each swipe is saved, and after every like the app asks its recommender for more movies based on everything the user has liked so far. Movies already swiped are never shown again, and filters for minimum rating and maximum runtime narrow the queue.

Code layout

The React frontend (movierecs) is split into components, hooks and utils. The recommender lives in utils. The backend (server) is a small Express API with two routes: one saves a swipe and one returns the full swipe history, newest first. Swipes are stored in MongoDB.

Key decisions and why

Swipes are saved on the server, so liked movies and history are still there after a reload. Card animation uses Framer Motion, and the recommender runs in the browser with TensorFlow.js, so the backend does not need a machine-learning service.

Tech stack

  • Frontend: React, Vite, Framer Motion
  • Recommendations: TensorFlow.js
  • Backend: Node.js 18+, Express
  • Database: MongoDB with Mongoose
